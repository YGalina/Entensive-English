## 0. Суть изменения одним абзацем

Сейчас продукт — **машина входа**: киносеанс, узнавание, SRS, чтение, shadowing, звуки, печать. Оба аудита и вся наука корпуса сходятся: для цели «заговорить» этого мало — рецептивно-продуктивный разрыв закрывается только производством речи (pushed output, продуктивное извлечение «значение→форма», корректирующие подсказки). Новая архитектура сохраняет вход как актив и достраивает четыре недостающих слоя: **(1) контур вывода** (статус дня, фразы, голос, объяснение), **(2) модель Цель→Программа→Задача→«что я могу»**, **(3) настоящую серверную память** (БД вместо JSON-снапшота) и **(4) честное измерение** (часы по Cambridge-ориентирам, внешние срезы, тренировочный режим вместо стрика).

Красные линии, встроенные в архитектуру (не только в маркетинг): никаких «980 слов в подсознание», «B2 за 6 месяцев с гарантией», «альфа-волны ускоряют», «речь всплывёт сама». Состояние (музыка/дыхание/настрой) остаётся — как регуляция и антивыгорание.

## 1. Целевая архитектура: пять слоёв

```
┌──────────────────────────────────────────────────────────────┐
│  ПРИЛОЖЕНИЯ            apps/web (Next.js)   apps/mobile (Expo)│
│  день-как-тренировка, онбординг цель-first, output-экраны     │
├──────────────────────────────────────────────────────────────┤
│  ДОМЕН (@ie/core)      goal / program / dayplan / srs v2      │
│  output / feedback / capability / assessment / timelog        │
├──────────────────────────────────────────────────────────────┤
│  КОНТЕНТ (@ie/core/data)  словари, паки, chunks/коллокации,   │
│  книги (Gutenberg), кураторские видео-блоки, drill-уроки      │
├──────────────────────────────────────────────────────────────┤
│  ПЛАТФОРМА (@ie/media, storage)  TTS, музыка, ЗАПИСЬ ГОЛОСА,  │
│  storage-adapter (local-first)                                │
├──────────────────────────────────────────────────────────────┤
│  СЕРВЕР (apps/web/api)  Postgres + журнал событий, синк v2,   │
│  auth, согласия/приватность, LLM-фидбэк, эксперимент-флаги    │
└──────────────────────────────────────────────────────────────┘
```

Принцип не меняется: **local-first**. Всё работает офлайн через storage-adapter; сервер — источник долговременной памяти, синка и того, что локально жить не может (записи голоса, фидбэк, внешние срезы).

## 2. Новая доменная модель (главная работа)

Сегодня система видит только «сколько был внутри и какие слова узнал» (`ie_prefs / ie_srs / ie_time / ie_wpm`). Не видит, что человек **произвёл**. Новые сущности:

### 2.1 Goal / Program (переработка `outcome.ts` + `data/program.ts`)

```ts
type Goal = {
  id: string;
  lifeGoal: string;          // «к декабрю 2026 B2, чтобы работать в среде»
  domain: "move" | "work" | "meetings" | "study" | "travel" | "unlock-speech";
  currentLevel: Level;       // из levelcheck v2
  targetLevel: Level;
  deadline?: string;         // ISO-дата; необязательна
  weeklyMinutes: number;     // реальный бюджет времени
};

type ProgramV2 = {
  goalId: string;
  hoursBudget: { perStep: number; note: "cambridge-glh" }; // 180–220 ч/шаг, диапазон, не обещание
  focusDomains: string[];    // темы под жизнь: health, money, interviews…
  weekTemplate: WeekBlock[]; // input/выход/повтор/состояние по дням
  checkpoints: Checkpoint[]; // ежемесячные срезы
};
```

Что меняется по сравнению с текущим кодом:
- `outcome.ts`: константа `SPEECH_EMERGES_DAYS = 180` («речь всплывёт сама по Крашену») **удаляется** — аудит прямо помечает это как хрупкое обещание. Часовой якорь остаётся (`HOURS_PER_LEVEL` ≈ 200, показывать как диапазон 180–220 и «ориентир, не гарантия»).
- `data/program.ts`: статичный «Интенсив 14 дней» перестаёт быть единственной программой. Программа **генерируется** из Goal (домен + часы + уровень); 14-дневный интенсив остаётся одним из шаблонов.

### 2.2 OutputArtifact — сердце нового слоя

```ts
type OutputArtifact = {
  id: string;
  type: "morning-phrase" | "status" | "essay" | "explanation" | "speech";
  promptId?: string;         // какое задание породило
  text?: string;
  audioRef?: string;         // локальный uri / серверный url после синка
  words: string[];           // какие слова из SRS человек употребил
  createdAt: number;
  privacy: "private" | "syncable";  // дневник и голос — приватные по умолчанию
};
```

Хранилище: новый ключ `ie_output` через существующий storage-adapter (mobile — expo-sqlite kv, web — localStorage), аудио — файл в sandbox приложения; на сервере — отдельная таблица + object storage.

### 2.3 SRS v2 — продуктивное направление

Наука корпуса (Strong): извлечение строго специфично направлению. «Увидел слово → узнал» тренирует рецептив; для речи нужно «значение → форма». Расширение `srs.ts`, **не новый движок**:

```ts
type SrsCard = {
  // существующие поля…
  direction: "recognize" | "produce";  // produce: показываем смысл на L1 → человек говорит/пишет форму
};
```

Правило конвейера: слово, стабильно узнаваемое (reps ≥ N, interval ≥ M дней), автоматически порождает produce-карту. Так «600 слов в узнавании» честно превращаются в «N слов вышли в активный запас».

### 2.4 Feedback — корректирующие подсказки

Наука (Strong): prompts > recasts — подсказка к самоисправлению лучше готового исправления.

```ts
type Feedback = {
  artifactId: string;
  kind: "prompt";            // не «красная ручка»
  hints: string[];           // «попробуй прошедшее время», «скажи короче», «начни с I have…»
  source: "rules" | "llm";   // сначала правила по частым L1-ошибкам, потом LLM
};
```

Этап 1 — офлайн-эвристики (типовые ошибки L1-русских: артикли, времена, кальки коллокаций «делать решение → make decision»). Этап 2 — LLM (Claude API) на сервере, только для synced-артефактов и с согласия.

### 2.5 Capability — «что я теперь могу»

```ts
type Capability = {
  id: string;                // canExplainSymptom, canSummarizeVideo, canAskFollowUp…
  domain: string;
  evidence: string[];        // id артефактов/срезов, подтверждающих
  unlockedAt?: number;
};
```

Это центральная метрика прогресса вместо «слов за день». Экран профиля/программы отвечает: «могу описать симптом врачу», а не «стрик 11».

### 2.6 Assessment — внешние срезы

```ts
type Assessment = {
  kind: "vocab-check" | "speaking-sample" | "external";
  level?: Level; sampleRef?: string; at: number;
};
```

Ежемесячный срез: levelcheck v2 (уже есть) + 2-минутный speaking sample (запись, вначале — самооценка по рубрике, позже — человеческая контрольная точка из MVP-A).

## 3. День v2: куда встраивается вывод

`DAY_STEPS` (dayplan.ts) получает шаги вывода — по аудиту, дёшево и ежедневно:

| Когда | Шаг | Механика | Наука |
|---|---|---|---|
| После настройки | **Утренняя фраза** | 1 фраза о себе, голосом или текстом | запуск речевого контура, низкие ставки |
| После киносеанса | **Извлечение 5–7 слов** | смысл на L1 → английская фраза | retrieval «значение→форма» (Strong) |
| В блоке видео/чтения | **Объясни своими словами** | пересказ одной мысли | protégé-эффект, pushed output |
| Вечером | **Статус дня** | 1–3 предложения + опционально 30 сек голосом | pushed output + социальный формат |
| Вечером | **Мягкие подсказки** | prompts по статусу | corrective feedback (Strong) |

`/evening` сохраняет артефакт дня, а не только тихий повтор. Позже (не в первой фазе): монолог 4/3/2 для беглости и pre-task planning (10 мин план на L1 для уверенных уровней — из GAP-отчёта).

## 4. Сервер и данные

### 4.1 Postgres вместо JSON-снапшота

Сейчас: `.data/store.json`, синк last-write-wins всего снапшота. Целевая схема (Drizzle ORM в apps/web):

`users`, `goals`, `programs`, `srs_cards`, `time_entries`, `output_artifacts`, `feedback`, `capabilities`, `assessments`, `consents`, `sync_events`.

### 4.2 Синк v2 — журнал событий, не снапшот

Клиент шлёт append-only события (`srs-answer`, `time-add`, `artifact-created`…) с локальными id и часами; сервер сливает идемпотентно. Снапшот остаётся как fallback и для миграции старых данных. Это убирает конфликт last-write-wins между телефоном и вебом.

### 4.3 Приватность (обязательная часть, не «потом»)

- Голос и дневники — **private по умолчанию**, синк только после явного согласия (сущность `consents`).
- Экспорт всех данных и полное удаление — API с первого дня схемы (152-ФЗ уже в спеке).
- LLM-фидбэк — только по согласию, с указанием, что текст уходит на обработку.

## 5. Механики: оставить / переосмыслить / добавить (сводно из обоих аудитов)

| Механика | Решение | Архитектурное следствие |
|---|---|---|
| SRS, чтение, shadowing, звуки, печать | **Оставить** — позвоночник | без изменений, кроме SRS v2 |
| Музыка/дыхание/настрой | **Оставить как состояние** | регистр текстов: «фокус и мягкий вход», не «альфа-волны» |
| «600–980 слов/день» | **Переосмыслить** | UI-копия: «в потоке/узнавании» + вечером «что я теперь могу»; убрать числа-обещания из заголовков |
| Стрики | **Переосмыслить** | «Тренировочный режим: 42 минуты сегодня»; язык спорта, не игры |
| «Речь всплывёт через 6 мес» | **Убрать** | удалить `SPEECH_EMERGES_DAYS`, заменить на output-контур |
| Гарантия уровня к дате | **Убрать** | процессная гарантия в monetization, не в домене |
| Активный вывод | **ДОБАВИТЬ в ядро** | §2.2–2.5, §3 |
| Кураторские видео преподавателей | **Добавить** | контент-сущность `TeacherBlock`: youtubeId + тайминги + chunks + shadowing-фрагменты + output-задание; только официальный embed, партнёрство — отдельно |
| Chunks/коллокации | **Добавить** | пак-формат в `@ie/core/data`: частотные коллокации с L1-ловушками («make a decision», не «do») |

## 6. Этапы разработки

Каждая фаза — зелёная по всему набору проверок: `tsc` mobile+web, `npm run test:unit`, web build + e2e, `expo export` iOS, превью-скриншоты. Web не ломается ни на одной фазе.

### Фаза A — Output-контур локально (2–3 недели работы, самая ценная)
Без сервера, целиком на storage-adapter — сразу проверяет главную гипотезу продукта.
- `@ie/core/output.ts`: OutputArtifact + ключ `ie_output` + хуки.
- SRS v2: поле `direction`, конвейер recognize→produce, экран продуктивного извлечения.
- День v2: утренняя фраза, извлечение 5–7 слов, вечерний статус в `/evening` (web) и в мобильных ритуалах.
- Запись голоса: `@ie/media` recording (expo-audio на mobile, MediaRecorder на web), приватно, локально.
- Фидбэк-эвристики (rules) по типовым L1-ошибкам.
- Профиль: «фраз создано / статусов написано / записей голоса» рядом с часами.

### Фаза B — Цель→Программа→Способность (2 недели)
- `@ie/core/goal.ts` + генератор ProgramV2; `outcome.ts` переработан (часы-диапазон, без «всплывёт сама»).
- Онбординг v3 (web+mobile): порядок из аудита — родной язык → язык интерфейса → жизненная цель → срок/уровень → реальные минуты (с честным «при таком темпе шаг уровня ≈ N месяцев — ориентир») → интересы → «программа собрана».
- Capability-вехи: стартовый набор по доменам, разблокировка от артефактов.
- Рефрейм UI: стрик → тренировочный режим (i18n-словарь, оба приложения).

### Фаза C — Сервер: Postgres + синк v2 + приватность (2–3 недели)
- Drizzle-схема (§4.1), миграция снапшотов, журнал событий, согласия, экспорт/удаление.
- Загрузка аудио-артефактов (object storage), только по согласию.
- Синк конфликтов: идемпотентный merge журнала.

### Фаза D — Измерение и фидбэк (2 недели)
- Assessment: ежемесячный срез (levelcheck + 2-мин speaking sample с рубрикой самооценки).
- LLM-фидбэк (Claude API) на статусы/эссе: prompts-подсказки, серверный, по согласию.
- Дашборд «что я могу» в профиле/программе.

### Фаза E — Контент-конвейер (параллельно C/D)
- `TeacherBlock` формат + 3 пилотных блока (embed, тайминги, chunks, shadowing, output-задание).
- Пак коллокаций с L1-ловушками; расширение drill-уроков.
- Копирайт-свип всего i18n по регистру безопасности (§5, таблица «нельзя/можно» из аудитов).

### Фаза F — Эксперименты (после A+B, на живых пользователях)
Инфраструктура флагов + два дешёвых эксперимента из аудитов:
1. **Output A/B**: вход+SRS vs вход+SRS+вечерний статус+голос → completion, уверенность речи, срез до/после.
2. **Цель-first онбординг** vs текущий → завершение онбординга, retention недели 1.

## 7. Что НЕ делаем (осознанно)

- Свой AI-собеседник/аватары — рынок насыщен, перенос не доказан; наш дифференциатор — конвейер вход→вывод→измерение.
- Гарантия уровня к дате — заменена процессной гарантией (уровень monetization-документа).
- Рехостинг видео преподавателей — только официальный embed; партнёрство отдельным треком.
- Лиги/социальные рейтинги — документированная тревога и смещение к лёгкому.
- Mobile-only стратегия — глубокая работа (письмо, разбор, оценивание) живёт на вебе; телефон — объём и ритуалы.

## 8. Риски

| Риск | Смягчение |
|---|---|
| Output-шаги увеличат трение дня → падение completion | шаги микроскопические (1 фраза), пропускаемые; эксперимент F-1 измеряет |
| LLM-фидбэк ошибается | только prompts-подсказки (не «исправления»), тон без оценки, человек в контуре на PRO |
| Синк v2 сложнее снапшота | снапшот остаётся fallback; журнал вводится поключно (сначала `ie_output`) |
| Голос = персональные данные | private-by-default, согласия, экспорт/удаление с первого дня схемы |
| Честные часы проигрывают маркетингу обещаний | эксперимент «честность vs число» из аудита; история основателя как доверие |

---

*Порядок фаз выбран так, чтобы главный продуктовый разрыв (нет вывода) закрывался первым и без серверной зависимости, а самая дорогая работа (БД/синк) шла, когда output-слой уже доказал себя на устройстве Галины.*
