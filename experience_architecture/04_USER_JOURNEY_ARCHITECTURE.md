## СКВОЗНЫЕ ИНВАРИАНТЫ (действуют во ВСЕХ путях; ниже не повторяются)

- **Один следующий шаг.** Path всегда предлагает ровно один ведущий шаг; кладовые латеральны.
- **Решения — по явному выбору или каноническому наблюдаемому событию, никогда по выводу о состоянии.** Поведение направляет адаптацию задачи, не диагноз.
- **Выход всегда валиден.** Для учебной задачи завершает; для протокольного этапа сохраняет промежуточное без completion.
- **Прерывание не теряет работу.** Черновик возобновляем; иммутабельность и завершённость — с явной отправки; свидетельство не пересоздаётся.
- **Продукция первична — три различных состояния.** *Факт выполнения* (она сказала своё — переживание) отделён от *локального черновика* (persistent, возобновляем, не свидетельство) и от *однократно принятого свидетельства/артефакта* (иммутабельно — с явной отправки). Недоступность AI/сети не отменяет попытку, но и **не подделывает подтверждённое сохранение**; повтор после сбоя не создаёт дубликат (идемпотентность по явной отправке).
- **Без красного, без пустой похвалы, без стрика; пауза — не потеря.**
- **Заявление не превышает реализованный класс свидетельства;** письменное ≠ устное.
- **Голос приватен и не анализируется.** Holdout защищён сквозь все поверхности.
- **Психология — поддержка, не результат.** Продукт не измеряет и не интерпретирует состояние.

**Сквозные типовые провалы/восстановления** (в путях помечаются кратко): затруднение при производстве → адаптация задачи **только по явному выбору ученицы или заранее определённому наблюдаемому событию задачи** (не по выводу о её состоянии), опускается **одна** из восьми осей (опора · планирование · темп · аудитория · оценка · своё содержание · ретрай · модальность), ретрай; техническая недоступность → см. «Продукция первична»; прерывание → возобновление черновика; язык утраты → запрещён, заменён «всё на месте». «Freeze» — не наблюдаемое состояние и не диагноз; продукт его не выводит.

## 1. ONBOARDING · вход в продукт

- **Цель:** превратить пришедшую в участницу, которая узнала себя и зафиксировала честную базовую линию — **не обходя протокол**.
- **Состояния:** Entry Gateway → узнавание проблемы (не лекция; «это про меня») → Profile Entry (пять наблюдаемых признаков; «недостаточно данных» легально) → создан Learner Profile → Path: первый ведущий шаг = **Претест (baseline, до любой практики)** → первая учебная сессия.
- **Решения:** подходит ли профиль (решает человек/Галина; «недостаточно данных» → решение человека, **не** автоотказ); приватность объявляется действием (первая продукция наедине).
- **Провалы:** онбординг-как-лекция (анти-паттерн, исключён); попытка вставить тренировочную продукцию **до претеста** → загрязнение baseline; отсев подходящей из-за ошибки диагностики.
- **Восстановление:** «недостаточно данных» → не отсев, а решение человека/лист ожидания; уход до претеста → Resume Router возвращает к незавершённому онбордингу.
- **Успех:** создан профиль **И** завершён претест (baseline как свидетельство). *Разрешение напряжения:* первая произнесённая фраза — сильнейший момент — намеренно наступает в **сессии 1 после претеста**, потому что базовая линия обязана быть до практики (конституция). Онбординг ведёт к ней кратчайшим путём, но не ценой протокола.

## 2. FIRST SESSION · первая сессия

- **Цель:** первая произнесённая своя фраза — безопасно, наедине (сильнейший retention-момент).
- **Состояния:** Path → Daily Cycle: встреча (связный контекст) → извлечение (лесенка опоры) → производство (своя фраза о себе, письменно) → произнесение вслух (приватный артефакт, не оценивается) → AI Summary (после, по тексту) → Path (маленькая завершённость).
- **Решения:** глубина опоры (явный выбор/наблюдаемое событие); записывать голос или нет («дальше без записи — можно»).
- **Провалы:** freeze при производстве; перегрузка; недоступность AI Summary; прерывание внутри шага.
- **Восстановление:** freeze → одна ось вниз; AI недоступен → продукция завершена, не переотправляется; прерывание → черновик возобновляем.
- **Успех:** создан первый артефакт продукции, зафиксирован как **process/task-performance**, не заявление о владении. **Сообщение о результате наследует фактическую модальность:** если записан голос — «ты произнесла это» (устный артефакт, не proficiency-claim); если только текст — «ты написала своё» (письменное **не** называется произнесённым). «Это сказала ты» — только при наличии голосового артефакта.

## 3. FIRST WEEK · первая неделя

- **Цель:** пережить первый ощутимый сдвиг — «что стало легче», а не «сколько часов».
- **Состояния (опыт типичной недели, не протокольный календарь):** введение единиц (Daily Cycle) → возврат по **produce-SRS** → повтор ранней задачи (услышать прирост) → недельное отражение (факты процесса, без «подряд»). Число дней и порядок — ответственность runtime-sequencing; недельная норма — рекомендация, не гейт и не наказание за иной темп.
- **Решения:** режим по силам (короткий/глубокий день); темы interleaved.
- **Провалы:** выпадение из ритма на 2–3-й день; скука; ожидание «уже свободно» → разочарование.
- **Восстановление:** пропуск → recovery-маршрут (не тратит программу); честное «данных пока мало» вместо ложного прогресса.
- **Успех:** несколько production-артефактов + возврат просевшего; повтор ранней задачи даёт ощущение «легче» (**личное переживание**, не outcome-claim).

## 4. RETURNING LEARNER · привычный возврат (без разрыва)

- **Цель:** бесшовно продолжить путь — один следующий шаг уже ждёт.
- **Состояния:** Entry → Resume Router → Path: current step (проекция runtime) → Daily Cycle или следующий **открытый** протокольный этап.
- **Решения:** продолжить ведущий шаг vs латерально в кладовую (не продвигает путь).
- **Провалы:** неоднозначность «где я был»; латеральный уход воспринят как продвижение.
- **Восстановление:** Path всегда знает один следующий шаг; Back из кладовой → источник входа.
- **Успех:** продолжила цикл без когнитивного налога «что делать».

## 5. MISSED DAY · пропущенный день (разрыв ≥2 календарных дней)

- **Цель:** вернуть без стыда; пропуск = пауза, не потеря.
- **Состояния:** Entry после gap → Path фиксирует пропуск по **каноническому runtime-правилу** (наблюдаемое событие: ≥2 календарных дней от последней практики, в часовом поясе ученицы) → предлагает **recovery** → recovery-сессия. Ровно один пропущенный день **не** считается пропуском — это обычный возврат (путь 4).
- **Решения:** принять предложенный recovery. Полная сессия остаётся достижимой по **явному намерению** ученицы, но **не показывается как второй равноправный ведущий шаг** — на ведущей линии один шаг (recovery), альтернатива не конкурирует за внимание как параллельный CTA.
- **Провалы:** язык утраты → уход; recovery как наказание; альтернатива, показанная как второй равный маршрут.
- **Восстановление:** ноль языка утраты; recovery не тратит программу; один показанный ведущий шаг.
- **Успех:** завершён короткий возврат (см. путь 6 — completed recovery-событие); `sessionsCompleted` без изменений; ритм восстановлен.

## 6. RECOVERY · сессия возврата

- **Цель:** короткий настоящий возврат — несколько всплывающих слов + одна своя фраза, без нового груза.
- **Состояния:** Path (recovery предложен) → Recovery Session: возврат due-единиц (SRS) → одно производство (главный вопрос) → голос опц. → резюме → Path. Recovery-событие в журнал; **программа не тронута**.
- **Решения:** голос/без; выход в любой момент (валиден).
- **Провалы:** воспринята как «неполноценная»; ошибочный расход программы; **открыть recovery и сразу выйти → ложное completed-событие** без возврата единиц и продукции.
- **Восстановление:** «настоящая практика» — по переживанию; архитектурно recovery ≠ расход курса; **минимальная обычная сессия наследует канонический контракт** (разные вещи). **Safe exit ≠ completed recovery:** выход в любой момент валиден, но `recoveriesCompleted +1` создаётся только после канонически определённого минимума содержимого (≥1 возврат единицы **и** одно производство); неполный выход — не завершение.
- **Успех:** recovery-сессия завершена **по минимальному содержимому**; авторитетный прогресс курса (runtime) не изменился.

## 7. AI CONVERSATION · разговор с AI

- **Цель:** после того как сказала своё — тёплое зеркало, ведущее дальше, никогда не перебивая.
- **Состояния:** *(резюме)* завершённый письменный вывод → AI Summary по тексту: признание → «ещё так говорят» → живой язык → грамматика к случаю → переход к практике → Path. *(диалог, [PLAN])* структурированная репетиция как ступень соц. лестницы.
- **Решения:** перейти в предложенную практику или нет.
- **Провалы:** соблазн перебить вслух (**запрещён**); AI недоступен; принять AI-успех за доказательство живого (запрещён, помечен ai≠human); отдать голос на анализ (запрещён).
- **Восстановление:** продукция первична — недоступность резюме не делает вывод незавершённым; резюме — **transient-проекция**, истина — артефакт (при повторе может регенерироваться, продукцию не меняет).
- **Успех:** показано резюме по её тексту; продукция завершена; ни балла, ни оценки владения; ни одного вмешательства во время речи.

## 8. LIBRARY EXPLORATION · исследование библиотеки

- **Цель:** принести живой язык из своей жизни в путь; кладовая, не витрина для залипания.
- **Состояния:** латеральный вход в Library → поиск/просмотр (YouTube-поиск [IMPL]) → **латеральный учебный запуск** → передан Daily Cycle (**без curriculum-эффекта**; возврат → Library) ИЛИ материал как **шаг дня** (из Path; curriculum-эффект; возврат → Path). Import-to-lesson «переведи свою жизнь» [FUT].
- **Решения:** латеральный запуск vs путь; импорт своего [FUT].
- **Провалы:** библиотека как контент-витрина → потребление входа без вывода (ловушка 15 лет); **holdout-единица всплывает в материале/поиске** → загрязнение; русские субтитры как отдых.
- **Восстановление:** материал ведёт к output; honest процент «моё». **Holdout-защита разграничена:** на **контролируемых** поверхностях (наш каталог, наши учебные объекты) защищённая единица гарантированно не предъявляется; **неконтролируемую** встречу (внешнее YouTube-видео, импорт из жизни) предотвратить нельзя — она **фиксируется как exposure/contamination** и учитывается в интерпретации свидетельства (ADR-016), а не считается «чистой».
- **Успех:** материал завершился производством (не пассивным просмотром); путь не подделан вторым источником прогресса.

## 9. SHADOWING · шэдоуинг

- **Цель:** просодия/беглость имитацией — чтобы речь звучала легче; приватно.
- **Состояния:** материал → **гейт понимания** → шэдоуинг → приватный голос-артефакт (не оценивается).
- **Решения:** продолжить/выйти; темп.
- **Провалы:** имитация без понимания (попугай каши); оценка произношения как экзамен; анализ голоса (запрещён; ASR — [FUT]); гейт реализован через process-активность, самооценку или скрытый proficiency-вывод.
- **Восстановление:** гейт **привязан к каноническому лингвистическому evidence-правилу понимания** (D2), с состоянием `insufficient evidence`, когда данных мало; психологические и shadow-сигналы в гейте **не участвуют**. Голос приватен; «носительский акцент» и красная оценка запрещены.
- **Успех:** разборчивость/лёгкость выросла (ощущение); голос — её приватный артефакт; в MVP никакой оценки произношения.

## 10. COMMUNITY · сообщество [PLAN/FUT]

- **Цель:** войти в живое общение **своим выбором**, по лестнице убывающей приватности, безопасно.
- **Состояния:** приватная продукция → асинхронный обмен артефактами (реакции, не оценки) → структурированный AI-диалог (репетиция) → направляемая пара (опоры, право выйти) → малый онлайн-клуб → [FUT] офлайн/события.
- **Решения:** каждый шаг — её **явный выбор** (не гейт готовности); отказ/выход в любой момент.
- **Провалы:** неготовая экспозиция → откат, подтверждение «я не могу»; допуск по «готовности» (**запрещён**); клуб как случайная болталка → новая рана; отказ создаёт тупик/повторное давление.
- **Восстановление:** допуск по выбору, не по готовности; **отказ/выход — завершённые безопасные состояния**, путь продолжается без штрафа; клуб с правилами (можно молчать, выход в один тап).
- **Успех:** доброволец сделала следующий социальный шаг своим выбором. *Честность:* перенос AI→человек — `[U]`, измеряется research-пилотами (H6/H10), **не заявляется** как достигнутый.

## 11. MILESTONE · момент успеха

- **Цель:** пережить **присвоенный** собственный успех — лестница моментов, не бейдж.
- **Состояния:** первый артефакт («это сказала ты») → удержание («слова всплывают») → автоматизация («вышло само») → перенос («всплыло где не учила», «сказала живому человеку»). Каждый — привязан к **классу и модальности** свидетельства.
- **Решения:** — (переживание, не выбор).
- **Провалы:** подаренная похвала против опыта (обесценивает); milestone как gamified badge/streak; заявление выше класса (письменное за устное, частота за удержание).
- **Восстановление:** каждый успех = факт, трассируемый к свидетельству; «далась легче» — личное переживание, не outcome-claim; где класса мало — «данных пока мало».
- **Успех:** человек присвоила конкретный факт (**гордость, не похвала**); заявление не превышает реализованный класс.

## 12. SUBSCRIPTION · подписка [PLAN]

- **Цель:** честный обмен ценности — **механизм, не эффект** (Г-4); без тёмных паттернов.
- **Состояния:** опыт ценности (первая сессия + артефакт) → честное предложение (механизм: «тренируешь именно доставание слова в речь», не «заговоришь через месяц») → выбор плана → оплата (совершает сама пользовательница) → доступ. Отмена — безопасное завершённое состояние, **данные остаются**.
- **Решения:** подписаться/нет; отменить/приостановить.
- **Провалы:** обещание эффекта вместо механизма (запрещено); ложная срочность/манипулятивный dunning; отмена как тёмный паттерн; paywall **до** опыта ценности.
- **Восстановление:** честные claims; отмена без тёмных паттернов.
- **Ограничение (governance).** Из этого пути **обязательны только уже ратифицированные конституцией правила**: заявление — механизм, не эффект (Г-4); без тёмных паттернов; заявление ≤ реализованного класса свидетельства. Конкретные решения — момент paywall, состав subscription-состояний, семантика pause/cancel, сохранение данных после отмены — **не являются замороженной архитектурой** и вводятся только через разрешённый governance-механизм (ADR / Architecture Resolution / ратификация владельца), а не этим Journey. Здесь они — предложение, не мандат.
- **Успех:** осознанное решение с честной информацией; ни одно заявление не превышает реализованный класс свидетельства.

## 13. NOTIFICATIONS · напоминания (жизненный цикл контракта)

- **Цель:** тихий зов в выбранное ею время; вернуть без вины.
- **Состояния:** opt-in (**владелец — Profile**) → scheduled (+timezone) → delivered → {tapped → **актуальное состояние Path** | dismissed | missed} → (permission-denied | disabled/opt-out | stale после смены Path).
- **Решения:** opt-in/out; время; тап/отклонить.
- **Провалы:** guilt-механика/стрик (**запрещено**); напоминание ведёт в устаревший шаг (stale); повторный запрос запрещённого разрешения; missed спутан с сознательным отказом → давление; создание второго входа.
- **Восстановление:** вход из напоминания **всегда → актуальное состояние Path** (не сохранённая цель); permission-denied ≠ opt-out; без вины; один вход.
- **Успех:** напоминание доставлено по контракту и привело в актуальный **один следующий шаг**, без давления.

## 14. INACTIVITY · длительная неактивность

- **Цель:** честный минимальный контакт без вины; при исчезновении — честно отпустить, не удерживать искусственно.
- **Состояния:** длительное молчание (наблюдаемое событие) → минимальный честный зов (не guilt) → {возврат → recovery-маршрут | продолжение молчания} → при исчезновении: честное прекращение давления; данные её, «всё на месте для возврата».
- **Решения:** вернуться или нет — её; продукт не наказывает и не манипулирует.
- **Провалы:** guilt-кампании/манипулятивный re-engagement (**запрещены**); искусственная вовлечённость ради подписки (запрещена, конституция); язык утраты.
- **Восстановление:** возврат — recovery «всё на месте»; ноль стыда.
- **Границы контакта (до Interaction Design):** «длительное молчание» и «зов» опираются на **канонические наблюдаемые пороги** и **жёсткий лимит частоты** — не серия re-engagement, а **не более одного честного контакта**; конкретные значения фиксируются на шаге 05 без вывода о мотивации.
- **Успех:** либо честный возврат без стыда, либо честное отпускание без манипуляции; ничто не «сгорело». *Отпускание — переживаемая рамка, не измеряемый outcome* (см. путь 15).

## 15. LONG-TERM PROGRESSION · долгий путь

- **Цель:** сдвиг «понимаю но не говорю» → «я говорю по-английски» — накоплением присвоенных доказательств; после B2 — образ жизни, продукт отступает.
- **Состояния:** structured acquisition (A2–B2, достройка недостающих слоёв и середина лестницы) → месячные срезы (**раздельные дорожки**, без CEFR-ярлыков кроме внешне-валидного среза) → guided expansion (B2→C1) → independent language life (C1+): свой контент, сообщество, наставничество; продукт **отступает** от ведущего к инструменту. *T-состояния — объяснительная рамка объект×задача×домен×модальность×условие, НЕ глобальная стадия человека и не этап продукта.*
- **Решения:** домены/элективы по выбору; наставничество.
- **Провалы:** единый ярлык уровня (**запрещён**, деморализует); ложная CEFR-точность; **T-стадия, присвоенная человеку целиком** (запрещена, второй progression system); имитация бесконечной вовлечённости ради подписки после B2 (**запрещена**); неровность дорожек как стыд.
- **Восстановление:** раздельные дорожки как ресурс, не стыд; уровень только из внешне-валидного среза; после B2 честнее отпустить в самостоятельность.
- **Успех:** способности «что могу» — заявляются **только по соответствующему классу Evidence Store** (артефакт — ссылка/иллюстрация, но сам по себе **не** доказательство способности без задержки, нового контекста, нужной модальности или валидной рубрики). **Сдвиг самоописания — переживаемая experience-гипотеза, НЕ измеряемый продуктовый outcome:** runtime и прогресс используют только лингвистические и наблюдаемые процессные данные; идентичность, мотивация и психологическая готовность **не измеряются**. Предельная цель — продукт стал не нужен как ведущий.

## 16. ASSESSMENT PROTOCOL · сквозной оценочный путь [IMPL·срез]

Раскладка уже утверждённого протокола во времени (порядок и переходы охраняются ядром; ничего нового не вводится).

- **Цель:** честно измерить удержание и употребление в новом контексте, не превращая оценивание в практику.
- **Состояния:** Претест (28: 22 тренируемых + 6 контрольных, фикс. порядок) · states `partial · complete` → **guard: 14 сессий Daily Cycle ЗАВЕРШЕНЫ И ≥14 календарных дней** (ожидание даты **не** заменяет сессии; `недоступно-до-даты` — информационное состояние) → Тест тренируемых (22) → Новый контекст (opportunity: `used · missed · insufficient-opportunity`) → Тест контрольных (6, отдельной последовательностью, только после нового контекста) → **явная однократная финализация** → Экспорт → повторный **read-only** экспорт.
- **Решения:** «не помню»/неверный ответ — **завершённые валидные свидетельства** (в оценивании нет опоры, подсказок и ретрая); внутри оценивания — только ответ, не смягчение задачи.
- **Провалы:** прыжок через этап; вход раньше guard; неполнота; выход, принятый за completion; повторный экспорт, создающий второе completion; контрольные до нового контекста → загрязнение.
- **Восстановление:** входы — только из Path в разрешённый момент; **выход из этапа ≠ completion** (сохраняет промежуточное, не удовлетворяет guard полноты); возобновление протокольного этапа — **через валидацию Protocol/Path**, не Resume Router; повторный экспорт — чистое чтение, второго completion не создаёт.
- **Успех:** протокол пройден в каноническом порядке; иммутабельные свидетельства раздельны (trained/holdout/new-context) с классом и модальностью; финализация однократна и отделена от чтения.

## СВОДКА: ПЕРЕСЕЧЕНИЯ И РАЗГРАНИЧЕНИЯ ПУТЕЙ

Чтобы избежать смешения близких путей:

| Путь | Триггер | Отличие |
|---|---|---|
| Returning learner | привычный вход, без разрыва | рутинное продолжение |
| Missed day | разрыв ≥2 дней | предложение recovery как ведущего шага |
| Recovery | принятие возврата | сама короткая сессия; не тратит программу |
| Inactivity | длительное молчание | честный минимум + возможное отпускание |
| Notifications | контракт напоминаний | доставка → актуальный Path |

Эти пять **не** дублируют учёт: только Daily Cycle (обычная сессия) двигает прогресс курса; recovery — отдельный счётчик; напоминание — маршрут, не шаг; неактивность — отсутствие событий, не наказание.

**Правило для шага 05 (Interaction Architecture).** Interaction задаёт события, запускающие переходы между состояниями каждого пути; Screen Specs (06) — поверхности. Все наследуют сквозные инварианты выше, модель владения IA и правило «решение — по выбору или наблюдаемому событию, никогда по диагнозу».

Одной фразой: **каждый путь ведёт к одному — чтобы взрослый человек сделал следующий безопасный шаг к собственному голосу, — и ни один путь не наказывает за паузу, не льстит вместо правды и не превращает её состояние в предмет измерения.**
