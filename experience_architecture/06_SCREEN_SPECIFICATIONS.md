# A. СИСТЕМА / МАРШРУТИЗАЦИЯ

## S1. Entry / Resume Router `[IMPL·срез]`
- **Назначение:** определить один следующий шаг при запуске/возврате и направить туда.
- **Вход:** запуск продукта; открытие из уведомления; возврат из фона.
- **Выход:** Onboarding (не онбордена) · прерванный шаг (черновик) · Path Hub · протокольный этап (только через валидацию Protocol/Path).
- **Требуемые данные:** наличие Profile; состояние Resumable Draft; актуальное состояние Path (проекция runtime); открытый протокольный этап.
- **Компоненты:** роутинг-логика (невидимая поверхность).
- **Состояния:** новая · возобновляемая · обычный возврат · возврат после паузы (→ предложение Recovery).
- **Граничные случаи:** повреждён/очищен локальный стор → как новая, с честным сообщением; открытие из stale-уведомления → в актуальный Path, не в сохранённую цель.
- **Загрузка:** быстрый роутинг; при неготовности данных — нейтральное ожидание, не «пусто».
- **Ошибки:** сбой чтения состояния → безопасно в Path Hub/Onboarding без потери принятых свидетельств.
- **Поведение AI:** нет.
- **Аналитика:** нет собственных событий (маршрутизатор); фиксирует источник входа (запуск/уведомление) как метаданные следующего события.

# B. ОНБОРДИНГ

## S2. Recognition (узнавание себя) `[IMPL~]`
- **Назначение:** первое впечатление «это про меня», не лекция и не тур.
- **Вход:** из S1 для новой.
- **Выход:** Profile Entry.
- **Требуемые данные:** нет (статичный смысловой ввод; факты/история — в лендинге/письмах).
- **Компоненты:** называние проблемы (понимаю, но замираю); одно действие «дальше».
- **Состояния:** единственное.
- **Граничные случаи:** возврат/закрытие → Resume Router вернёт сюда (онбординг не завершён).
- **Загрузка:** мгновенно.
- **Ошибки:** —.
- **Поведение AI:** нет.
- **Аналитика:** `onboarding-started`.

## S3. Profile Entry (пять признаков) `[IMPL·срез]`
- **Назначение:** зафиксировать наблюдаемый профиль входа; создать Learner Profile.
- **Вход:** из S2.
- **Выход:** Path Hub (первый шаг = Претест).
- **Требуемые данные:** пять признаков P1–P5; заметка.
- **Компоненты:** пять признаков-переключателей `да / нет / недостаточно данных`; поле заметки; сохранить-и-войти.
- **Состояния:** пустой · частично · все отмечены (можно сохранить).
- **Граничные случаи:** «недостаточно данных» — легально; решение о включении — человека, не автоотказ; повторный вход не перезаписывает завершённый профиль молча.
- **Загрузка:** локальное сохранение мгновенно.
- **Ошибки:** сбой записи → not-saved честно, вход не открывается до сохранения.
- **Поведение AI:** нет.
- **Аналитика:** `pilot-entry {profile, note}`.

# C. ВЕДУЩАЯ ЛИНИЯ

## S4. Path Hub (один следующий шаг) `[IMPL·срез]`
- **Назначение:** показать ровно один ведущий шаг и его «зачем»; латеральный доступ к кладовым.
- **Вход:** из S1; возврат из любой мастерской; вход из уведомления.
- **Выход:** соответствующая мастерская/этап одним намерением; латерально в Reference.
- **Требуемые данные:** актуальный Current Step (проекция Scheduler+Protocol); признак паузы; краткие факты процесса; наличие открытого протокольного этапа.
- **Компоненты:** карточка ведущего шага (заголовок + «зачем» + одно действие); блок фактов процесса (без vanity); латеральные входы в кладовые; при паузе — карточка Recovery (единственный ведущий шаг), полная сессия — по явному намерению, не второй равный CTA; при открытом этапе — этап как ведущий шаг; недоступный будущий этап — информационное состояние, не CTA.
- **Состояния:** обычный · пауза/Recovery · протокольный этап открыт · протокол недоступен-до-условий · пилот завершён (после финализации) · готов к финализации.
- **Граничные случаи:** одновременная доступность нескольких действий → всегда один показанный ведущий шаг; факты «данных пока мало» вместо нулей.
- **Загрузка:** проекция считается быстро; при неготовности — спокойное ожидание.
- **Ошибки:** рассинхрон проекции → показывает последнее известное безопасное состояние; никогда не подделывает прогресс.
- **Поведение AI:** нет.
- **Аналитика:** просмотр — не событие; действия ведут в события соответствующих экранов; факты процесса — проекция журнала, не новые записи.

# D. СЕССИЯ

## S5. Daily Cycle Session (6 шагов) `[IMPL·срез]`
- **Назначение:** дневной микроцикл до собственной фразы.
- **Вход:** из Path Hub («начать/продолжить»).
- **Выход:** Path Hub (маленькая завершённость); выход-в-любой-момент валиден (учебная задача).
- **Требуемые данные:** план сессии (новые единицы / возврат); связный текст дня; целевые единицы и промпты; produce-SRS due; грамматический контраст (в дни введения 2–4).
- **Компоненты (по фазам-состояниям):**
  1. *Прайминг* — единицы дня, тап-послушать; без заданий.
  2. *Встреча* — связный текст; тап-послушать / тап-перевод.
  3. *Извлечение* — реплика смысл→форма, **английского на экране нет**; ввод текстом (автокоррекция off); лесенка опоры (буква → выбор из 3 → показ+перепечатать) + ретрай.
  4. *Производство* — task-essential промпт о её жизни; свободный ввод; мягкий надж при отсутствии целевой формы/конструкции; кнопка «оставить как есть».
  5. *Голос* — опциональная приватная запись «скажи вслух»; прослушать; «дальше без записи — можно».
  6. *Резюме* — тёплая карточка **по написанному тексту**; плашка честности источника.
- **Состояния:** по фазам; частично пройдено (возобновляемо); завершено.
- **Граничные случаи:** прерывание внутри фазы → возобновление черновика без пересоздания свидетельства; тип сессии recovery → без нового материала (см. S6); недоступность голоса → произнести вслух, продолжить.
- **Загрузка:** не блокирует завершение; TTS/озвучка — неблокирующие.
- **Ошибки:** без красного; неверное извлечение → ступень опоры + ретрай; сбой сети → принятое сохранено, черновик возобновляем.
- **Поведение AI:** во время фаз 1–5 **отсутствует полностью**; на фазе 6 — резюме **после** завершённого письменного вывода (transient-проекция; недоступность не делает вывод незавершённым).
- **Аналитика:** `session-started` · `encounter{step}` · `retrieval-attempt{depth,latency(shadow)}` · `production-submitted{foundIds,grammar,satisfied}` · `voice-artifact{ref,privacy,analysed:false}` · `summary-shown` · `session-completed`. Латентность/глубина лесенки — shadow, не гейтят/не показываются.

## S6. Recovery Session `[IMPL·срез]`
- **Назначение:** короткий настоящий возврат после паузы, не тратящий программу.
- **Вход:** из Path Hub (Recovery — ведущий шаг).
- **Выход:** Path Hub.
- **Требуемые данные:** до 8 due-единиц; главный вопрос-производство.
- **Компоненты:** извлечение (возврат due) → одно производство → голос опц. → резюме.
- **Состояния:** как S5 без фаз введения.
- **Граничные случаи:** **safe exit ≠ completed recovery** — `recoveriesCompleted +1` только по минимуму содержимого (≥1 возврат единицы И одно производство); неполный выход не завершает.
- **Загрузка/Ошибки/AI:** как S5.
- **Аналитика:** `session-started{type:recovery}` · те же события производства · `session-completed{type:recovery}`; **прогресс курса не изменяется**.

# E. ОЦЕНОЧНЫЙ ПРОТОКОЛ (режим оценивания — без опоры/ретрая/награды/показа ответов)

## S7. Pretest (28) `[IMPL·срез]`
- **Назначение:** базовая линия письменного продуктивного извлечения по 22 тренируемым + 6 контрольным.
- **Вход:** из Path Hub (первый шаг после Profile Entry).
- **Выход:** Path Hub по завершении (полнота 28).
- **Требуемые данные:** фиксированный порядок 28; реплики смысл→форма.
- **Компоненты:** реплика смысла; ввод (автокоррекция off); «дальше» (при вводе); «не помню — дальше»; индикатор прогресса; плашка «это базовая линия, ответы не показываем».
- **Состояния:** partial · complete; возобновление пропускает уже записанные единицы.
- **Граничные случаи:** повтор записи единицы отклонён (иммутабельность); завершение только по полноте 28 и однократно.
- **Загрузка:** локально; не блокирует.
- **Ошибки:** без опоры/ретрая; неверный/«не помню» — завершённое свидетельство.
- **Поведение AI:** **отсутствует полностью.**
- **Аналитика:** `assessment-item{phase:pretest,itemId,verdict,exposure{group,pretestExposed,intentionallyReassessed}}` · `pretest-finished` · `holdout-assigned`.

## S8. Assessment Gate / Wait (недоступно-до-условий) `[IMPL·срез]`
- **Назначение:** честно объяснить, почему тест ещё закрыт.
- **Вход:** попытка войти в тест тренируемых раньше guard; из Path Hub.
- **Выход:** Path Hub.
- **Требуемые данные:** число завершённых сессий; дней от претеста.
- **Компоненты:** информационное состояние «откроется при 14 сессиях И 14 днях»; без CTA-конкуренции.
- **Состояния:** guard не выполнен (обе или одна причина).
- **Граничные/загрузка/ошибки:** guard считается ядром; прямой заход по ссылке ловится и показывает это состояние.
- **AI:** нет.
- **Аналитика:** нет записи (информационное).

## S9. Trained Assessment (22) `[IMPL·срез]`
- **Назначение:** удержание тренированных единиц; дельта к претесту.
- **Вход:** из Path Hub только при guard (14 сессий И ≥14 дней).
- **Выход:** → Новый контекст (S10) по полноте 22.
- **Требуемые данные:** 22 тренируемых в претестовом относительном порядке.
- **Компоненты:** как S7 (оценочный режим).
- **Состояния:** partial · complete; возобновление пропускает записанные.
- **Граничные случаи:** контрольные здесь недоступны (ядро отклоняет); завершение однократно по полноте.
- **AI:** нет.
- **Аналитика:** `assessment-item{phase:day14,...trained}` · `day14-finished`.

## S10. New-Context Task `[IMPL·срез]`
- **Назначение:** употребление тренированных единиц в нетренированном контексте (opportunity-модель).
- **Вход:** после завершения S9.
- **Выход:** → Holdout (S11).
- **Требуемые данные:** один нетренированный промпт; целевой набор возможностей (знаменатель).
- **Компоненты:** промпт; свободный письменный ввод (минимум длины — общая константа); опциональная приватная голосовая запись; отправка.
- **Состояния:** ввод · отправлено (однократно).
- **Граничные случаи:** пустой/пробелы/короче минимума → отклонение (не `insufficient-opportunity`); повтор отправки отклонён; строго **до** экспозиции контрольных.
- **AI:** нет.
- **Аналитика:** `new-context-submitted{statuses:used/missed/insufficient-opportunity,denominator,grammar,voice:{ref,private,analysed:false}}`.

## S11. Holdout Assessment (6) `[IMPL·срез]`
- **Назначение:** контроль test–retest/фона по 6 никогда-не-тренированным.
- **Вход:** только после нового контекста.
- **Выход:** → Path Hub с шагом «Завершить пилот».
- **Требуемые данные:** 6 контрольных отдельной последовательностью.
- **Компоненты:** как S7; плашка «контроль сравнения, не проверка тебя».
- **Состояния:** partial · complete.
- **Граничные случаи:** до нового контекста недоступны (ядро отклоняет); завершение однократно по полноте 6.
- **AI:** нет.
- **Аналитика:** `assessment-item{phase:day14,...holdout}` · `holdout-finished`.

## S12. Finalization (завершить пилот) `[IMPL·срез]`
- **Назначение:** явное однократное завершение данных, отделённое от чтения.
- **Вход:** из Path Hub после holdout.
- **Выход:** Path Hub (пилот завершён).
- **Требуемые данные:** признак завершённости всех трёх частей.
- **Компоненты:** объяснение «данные станут окончательными»; действие «завершить пилот».
- **Состояния:** готов к финализации · финализирован.
- **Граничные случаи:** финализация до всех частей отклонена ядром; повтор отклонён.
- **AI:** нет.
- **Аналитика:** `pilot-finalized`.

## S13. Export (выгрузка) `[IMPL·срез]`
- **Назначение:** передать данные пилота человеку на анализ.
- **Вход:** из Path Hub; финальная — только после финализации; черновик — до неё (помечен partial).
- **Выход:** системный шэринг JSON.
- **Требуемые данные:** состояние, журнал, produce-SRS, сводки (trained/holdout раздельно), ссылки голоса.
- **Компоненты:** действие «выгрузить»; при незавершённом — «выгрузить черновик».
- **Состояния:** финальный (после финализации) · черновой (partial).
- **Граничные случаи:** финальный экспорт до финализации отклонён; повторные выгрузки — **чистое чтение**, без событий/мутаций.
- **AI:** нет.
- **Аналитика:** финальный экспорт не создаёт новых completion-событий; черновой — `export-partial{reason}`.

# F. AI

## S14. AI Summary `[IMPL·срез]`
- **Назначение:** тёплое резюме после письменного вывода.
- **Вход:** автоматически после завершённого производства (фаза 6 S5).
- **Выход:** Path Hub / переход в предложенную практику.
- **Требуемые данные:** её письменный текст; найденные единицы; курируемые варианты «ещё так говорят».
- **Компоненты:** признание · «ещё так говорят» · живой язык · грамматика к случаю · переход к практике · плашка честности источника.
- **Состояния:** показано · недоступно/задержано (неблокирующе).
- **Граничные случаи:** недоступность резюме не делает вывод незавершённым; при повторе — из сохранённой копии или регенерация, продукцию не меняет.
- **Загрузка:** неблокирующая.
- **Ошибки:** сбой генерации → продукция уже завершена; честное «разбор появится позже», без потери.
- **Поведение AI:** только здесь, только после; никакого голоса, балла, оценки владения; ai≠human.
- **Аналитика:** `summary-shown{foundIds}`.

## S15. AI Structured Dialogue `[PLAN]`
- **Назначение:** структурированная репетиция диалога (ступень соц. лестницы).
- **Спец-глубина:** отдельная поверхность от S14; ≠ доказательство живого общения; тот же запрет вмешательства во время речи; статус Запланировано (после отдельного ADR runtime-генерации).

## S18. Progress `[PLAN]`
- **Назначение:** честное зеркало «что я теперь могу»; **проекция**, не гейт.
- **Вход/Выход:** латерально / источник.
- **Требуемые данные:** проекция Evidence Store + Journal; классы/модальности.
- **Компоненты:** способности «что могу» (только по классу свидетельства) наверху; факты процесса ниже; «данных пока мало» где класса нет; раздельные дорожки без CEFR-ярлыков (кроме внешне-валидного среза).
- **Состояния:** есть свидетельства · накопление (пусто честно).
- **Граничные случаи:** артефакт сам по себе — не capability-claim; письменное ≠ устное; ноль стрика/процентов курса.
- **Загрузка/Ошибки:** проекция; не гейтит.
- **AI:** нет.
- **Аналитика:** только чтение; ничего не пишет.

## S19. Library `[IMPL]` (каталог + YouTube-поиск)
- **Назначение:** кладовая живого языка; мост «переведи свою жизнь».
- **Вход:** латерально из Path Hub.
- **Выход:** источник входа; латеральный учебный запуск → Daily Cycle **без curriculum-эффекта** (возврат → Library); Path-шаг (день=слушание) → Path.
- **Требуемые данные:** витрина Content Bank; результаты YouTube-поиска [IMPL]; **holdout отфильтрован** на контролируемых поверхностях.
- **Компоненты:** каталог; поиск (материал); карточка материала; латеральный запуск; импорт «переведи свою жизнь» [FUT].
- **Состояния:** есть · пусто (приглашение принести своё); результаты поиска / нет ключа / нет согласия (разные состояния, S25/поиск).
- **Граничные случаи:** **неконтролируемая** внешняя встреча holdout (внешнее видео/импорт) не гарантируется отфильтрованной — фиксируется как contamination (ADR-016), не «чистая»; субтитры-как-отдых не поощряются (материал ведёт к output).
- **Загрузка:** поиск — неблокирующий; ошибка сети → честное состояние.
- **Ошибки:** нет ключа (технич.) ≠ нет согласия (privacy) — разные состояния.
- **AI:** нет (генерация уроков из импорта — [FUT], через валидатор).
- **Аналитика:** латеральный запуск не двигает прогресс курса.

## S20. Profile `[IMPL~]`
- **Назначение:** профиль, языки, приватность, **контракт напоминаний** (владелец).
- **Вход/Выход:** латерально / источник.
- **Требуемые данные:** предпочтения; статус приватности; контракт напоминаний.
- **Компоненты:** языки; тема (визуал — шаг 07); приватность (что локально/что уходит; голос не анализируется); настройки напоминаний (opt-in/out, время, timezone); авторизация/оплата — входы [PLAN].
- **Состояния:** обычный.
- **Граничные случаи:** displayName нейтральный (Галина — только лендинг/письма); permission-denied ≠ opt-out.
- **Загрузка/Ошибки:** локально.
- **AI:** нет.
- **Аналитика:** изменения контракта напоминаний/приватности — как настройки, не поведенческие метрики.

# H. КОНТЕНТНЫЕ МАСТЕРСКИЕ

## S21. Reading / Listening `[IMPL~]`
- **Назначение:** потребление материала, ведущее к производству.
- **Вход:** латеральный запуск из Library или шаг дня из Path.
- **Выход:** латеральный → Library (без curriculum-эффекта); Path-шаг → Path.
- **Требуемые данные:** материал; при Path-шаге — привязка к дню.
- **Компоненты:** материал; тап-послушать/перевод; передача в Daily Cycle для output.
- **Состояния:** просмотр · учебный запуск.
- **Граничные случаи:** библиотека-как-витрина исключена (материал → output); holdout как в S19.
- **Загрузка/Ошибки/AI:** нейтрально; AI нет.
- **Аналитика:** латеральное — не прогресс.

## S22. Shadowing `[IMPL~]`
- **Назначение:** просодия/беглость имитацией; приватно.
- **Вход:** из материала.
- **Выход:** источник.
- **Требуемые данные:** материал с транскриптом; **гейт понимания** (лингвистическое evidence D2 + `insufficient evidence`).
- **Компоненты:** проверка понимания (гейт) → шэдоуинг → приватная запись (не оценивается).
- **Состояния:** гейт не пройден (insufficient) · шэдоуинг · артефакт.
- **Граничные случаи:** без понимания не пускает; оценка произношения — [FUT]; голос не анализируется.
- **Загрузка/Ошибки/AI:** голос не анализируется; красной оценки нет.
- **Аналитика:** приватный голос-артефакт (ref, не анализ); гейт — по лингвистическому evidence, не psycho/shadow.

## S23. Story Engine `[PLAN]`
- **Назначение:** сборка своей истории из **освоенного**; присвоение.
- **Спец-глубина:** create-режим; читает освоенные единицы (SRS-проекция), производит Artifact; **не оценивается** как владение, не двигает Path; может питать обмен артефактами (ступень 1 сообщества). Статус Запланировано.

# I. СООБЩЕСТВО `[PLAN/FUT]`

## S24. Community Ladder (обмен → пара → клуб → офлайн)
- **Назначение:** войти в живое общение своим выбором, по лестнице убывающей приватности.
- **Спец-глубина (высокоуровнево, до research-пилотов):** ступени — асинхронный обмен артефактами (реакции, не оценки) · направляемая пара (опоры, выход в один тап) · малый онлайн-клуб (вопрос на столе, можно молчать) · [FUT] офлайн/события. Допуск — **по явному выбору, не по гейту готовности**; отказ/выход — завершённые безопасные состояния, путь продолжается без штрафа. Перенос AI→человек — `[U]`, не заявляется. Операционная модель (подбор, модерация, no-show) — отдельный ADR.

# J. ПОДПИСКА `[PLAN]`

## S25. Subscription / Paywall
- **Назначение:** честный обмен ценности — механизм, не эффект.
- **Спец-глубина:** обязательны только ратифицированные правила честности (Г-4: механизм не эффект; без тёмных паттернов; заявление ≤ класса свидетельства). Момент paywall, состав состояний, pause/cancel, сохранение данных — **не замороженная архитектура**, вводятся только через governance; здесь — предложение, не мандат. Отмена — как отказ/выход (завершённое безопасное состояние, данные её). Ввод платёжных данных — самой пользовательницей.

# K. СИСТЕМНЫЕ ПОВЕРХНОСТИ

## S26. Notification (доставка) `[PLAN]`
- **Назначение:** тихий зов; не экран, а доставляемая поверхность контракта (владелец — Profile).
- **Состояния исполнения:** scheduled(+timezone) · delivered · tapped · dismissed · missed · permission-denied · disabled · stale.
- **Вход/выход:** тап → **актуальное состояние Path** (не сохранённая цель); один вход.
- **Правила:** без guilt/стрика; для неактивности — Inactivity Contract (≤1 честный контакт); частота/пороги — Interaction Architecture.
- **AI:** нет.
- **Аналитика:** доставка/тап/пропуск — как состояния контракта, не поведенческие выводы; missed ≠ отказ.
