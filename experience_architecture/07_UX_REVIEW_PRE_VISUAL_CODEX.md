# Complete UX Architecture Review · Pre-Visual Gate

## Critical

### 1. «Никаких подсказок во время письма» запрещает лесенку извлечения

Interaction Architecture запрещает подсказки и коррекцию во время любого письма. Daily Cycle одновременно требует лесенку `первая буква → выбор → показ+перепечатать` внутри текстового извлечения. Визуальный дизайн не сможет выполнить оба правила: либо уберёт обязательную опору, либо допустит вмешательство во время свободной продукции. Минимальное исправление — ограничить режим полной тишины свободным письменным производством и речью; scaffolded retrieval должен оставаться отдельной учебной подзадачей с разрешённой опорой.

### 2. После досрочного завершения 14 сессий Path остаётся без следующего шага

Assessment открывается только при выполнении двух условий: 14 curriculum sessions и 14 календарных дней. Если сессии завершены раньше, S8 предлагает только информационное ожидание; новые curriculum sessions закончились, а assessment закрыт. Это нарушает инвариант «Path всегда показывает ровно один следующий шаг» и создаёт мёртвое состояние у наиболее активной участницы. Минимальное исправление — определить каноническое состояние Path в этом окне: либо честное завершённое ожидание до конкретной даты, которое не притворяется учебным действием, либо уже утверждённый некурсовой шаг, не загрязняющий assessment и не расходующий программу.

## Major

### 3. Претест остаётся первым длинным опытом неуспеха

Первое активное действие — 28 письменных baseline-items до первой собственной фразы. Для целевой аудитории это серия возможных «не помню» в самой хрупкой точке формирования доверия. Текущая защита ограничена кратким объяснением baseline. Минимальное исправление — специфицировать обязательный психологический контракт pretest: «не помню» является ожидаемым полноценным ответом, baseline не оценивает человека, а первая практика следует после него; без подсказок и без загрязнения baseline.

### 4. Mini-lessons отсутствуют во всех UX-слоях

Frozen Constitution включает AI mini-lessons with infographics как запланированное расширение AI coach. В IA, journeys, interactions и screens этой поверхности нет. Visual design не сможет сохранить место для уже утверждённой подсистемы. Минимальное исправление — добавить её существующий `[PLAN]`-статус, IA-владение, вход/выход и связь с практикой, не проектируя новое содержание.

### 5. Нет пути разрешения потери локальной целостности данных

S1 корректно блокирует продолжение старого Pilot при повреждённом authoritative store, но на этом journey заканчивается. Пользователь остаётся в честном, но безвыходном состоянии. Минимальное исправление — определить уже требуемый resolution journey: объяснение состояния, доступные подтверждённые варианты восстановления или явного нового старта и запрет молчаливого создания второй pilot identity.

### 6. Нет journey для результата профильного отбора

Onboarding допускает решение человека, `insufficient data` и waitlist, но после этого нет состояний ожидания, допуска или отказа. Минимальное исправление — определить короткий путь каждого уже заявленного результата с ясным статусом и без психологической интерпретации кандидата.

### 7. Habit loop не имеет cue при отказе от уведомлений

Архитектура привычки строится как cue → practice → internal reward, но единственный формализованный cue — opt-in notification. При permission denied или opt-out остаются routine и reward без запускающего события. Минимальное исправление — явно зафиксировать допустимое состояние habit contract без уведомлений и уже существующий пользовательский ритм/якорь как добровольный cue; без стрика, guilt или нового канала давления.

### 8. AI Summary имеет конфликтующий выход

S14 допускает два продолжения: вернуться в Path Hub или перейти в предложенную практику. При принципе одного следующего шага это может создать второй учебный маршрут непосредственно из feedback. Минимальное исправление — определить одно каноническое значение предложенной практики: либо это текущий next step Path, либо латеральное действие без curriculum effect; два равноправных CTA недопустимы.

### 9. Латеральный Library launch не имеет отдельной completion-семантики

Library передаёт материал в Daily Cycle без curriculum effect, но S5 использует `session-completed`, а S21 не определяет иной тип completion/event. Поэтому латеральная практика может случайно увеличить одну из 14 sessions или, наоборот, не сохранить выполненную работу вовсе. Минимальное исправление — связать источник запуска с уже заявленным curriculum-effect: Path-owned запуск может писать curriculum completion, Library-owned запуск — только process/artifact events.

### 10. Receptive-only session разрешена методологией, но отсутствует в journeys и screens

Experience и UX Architecture разрешают receptive-only день и переносят production contract на окно дня/недели. Screen Specifications содержат только шестишаговый Daily Cycle с обязательными retrieval + production для completion. Для Vertical Slice это допустимо, но полная UX architecture не содержит запланированного состояния легальной receptive-only session. Минимальное исправление — отметить этот уже разрешённый session type и его completion/progress semantics как `[PLAN]`, не меняя Pilot flow.

### 11. Cross-device continuation отсутствует как journey

Constitution закрепляет mobile/web и целевое кросс-девайс продолжение. UX описывает Resume Router и future sync states, но нет пути device A → pending sync → device B, conflict, stale state или accepted evidence already submitted elsewhere. Минимальное исправление — добавить planned cross-device journey с существующими authority/idempotency rules до проектирования обеих платформ.

### 12. Search architecture покрыта не полностью

UX Architecture определяет два поиска: material search и search of own words/artifacts/history. Screen Specifications реализуют только Library/YouTube search; для поиска своего нет поверхности, пути или состояния возврата. Минимальное исправление — добавить запланированную достижимость второго уже утверждённого search contract либо явно ограничить текущий visual scope material search.

### 13. Trainer/Admin journeys отсутствуют

Frozen Constitution включает planned Teacher Dashboard and Admin subsystems. Полная learner UX детализирована до screens, но связанные роли, входы, права и handoff human review отсутствуют полностью. Это особенно важно для будущего assessment review. Минимальное исправление — явно исключить эти роли из текущего visual scope либо добавить их уже утверждённый `[PLAN]` journey boundary; learner screens не должны неявно определять их полномочия.

### 14. Platform allocation отсутствует перед visual design

Constitution задаёт mobile как дом ежедневного ритуала/голоса и web как дом глубокой работы/progress/live с override, но Screen Specifications platform-neutral. Не определено, какие screens обязательны на обеих платформах, какие имеют default home и как сохраняется navigation state между ними. Минимальное исправление — зафиксировать существующее platform ownership и overrides для S1–S27 до создания platform-specific layouts.

### 15. Восемь task parameters выглядят реализуемыми одновременно

Верхние слои перечисляют восемь осей адаптации, а текущие screens конкретизируют только support и retry; часть остальных параметров частична или отсутствует по Constitution. Visual design может ошибочно создать controls для всех восьми или скрытую автоматическую адаптацию. Минимальное исправление — обозначить maturity каждой оси и применять one-axis rule только к реально реализованным параметрам; остальные остаются будущим DLE config layer.

## Minor

### 16. Discoverability кладовых задана только фактом наличия

S4 содержит «латеральные входы», но interaction contract не фиксирует их постоянную достижимость и поведение перехода Reference → Reference. Минимальное исправление — сохранить один не конкурирующий с CTA путь к Reference и определить, что переход между кладовыми не создаёт новый navigation stack или progress event.

### 17. Path Hub несёт слишком много равноправной информации

На одной поверхности находятся next step, причины блокировки, process facts, lateral references, Recovery и protocol state. Без приоритета эти элементы могут превратить Path в dashboard и увеличить decision load. Минимальное исправление — закрепить семантический приоритет: next step и его «зачем» являются единственным действием; остальные элементы информационные или латеральные и не конкурируют с ним.

### 18. Voice lifecycle не наследуется явно всеми voice-поверхностями

Полные permission/interruption/storage/playback states описаны в S5, но S10 и S22 ссылаются на голос без явного наследования того же lifecycle. Минимальное исправление — сделать S5 voice lifecycle сквозным контрактом всех recording surfaces.

### 19. Смена timezone после scheduling не определена

Reminder Contract хранит timezone, но не определяет, остаётся ли выбранное время локальным после путешествия и когда scheduled notification становится stale. Минимальное исправление — зафиксировать одно информационное правило пересчёта существующего расписания без изменения habit policy.

### 20. Maturity Path остаётся неоднозначной

S4 Path Hub помечен `[IMPL·срез]`, тогда как общая Path projection в IA является `[PLAN]`. Минимальное исправление — различить реализованный slice hub и planned product-wide Path, чтобы visual design не принял Pilot navigation за завершённую общую модель.

### 21. Между первой победой и первым отложенным evidence нет отдельного состояния ожидания прогресса

После первой фразы честный outcome ещё не измерим, а Progress обязан показывать `insufficient data`. Этот период может ощущаться как отсутствие движения. Минимальное исправление — использовать уже разрешённые process facts как временное состояние, не повышая их до retention, mastery или capability claim.
