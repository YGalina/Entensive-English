# Mobile and Web Learning Split

Date: 2026-07-14

Principle: platform assignment follows learning demand first, UX convenience second.

## 1. Platform Logic

Mobile is not reduced web.

Web is not a storage attic.

Mobile builds rhythm, voice, low-friction repetition and return.

Web builds depth, analysis, writing, long reading, grammar construction and progress review.

## 2. Activity Assignment

| Activity | Platform | Method reason | UX reason |
|---|---|---|---|
| Daily session | both, mobile primary | habit and input-output loop | phone is always available |
| Word flow | mobile focus, web optional | perceptual preview in short bursts | full-screen ritual works on phone |
| Context reading/listening | both | input must connect to output | phone short, web deeper |
| Context audio loop | mobile primary | listening repetition in small windows | headphones |
| Recognition SRS | mobile primary | micro retrieval | 3-5 min queues |
| Productive SRS | mobile primary | meaning→speech retrieval | voice in hand |
| "Say your own" | both | output every session | mobile voice, web text/longer |
| Pronunciation | mobile primary | recording and repetition | intimate, headphone-friendly |
| Shadowing | both | mobile for repetition, web for analysis | phone on walk, web big transcript |
| Grammar workshop | web primary; mobile micro | needs visual comparison and deliberate construction | keyboard/space |
| Phrase builder from audio | both | retrieval from listening | mobile short, web longer |
| Typing/motor channel | web only | keyboard motor memory | real keyboard |
| Reading books | both | extensive reading | mobile short, web long |
| Speed reading | web primary | attention and measurement | larger screen |
| Writing | web primary; mobile 3-4 lines | revision and genre work | keyboard |
| Role-play | both | speaking/interaction | mobile voice, web longer scenarios |
| AI conversation | both | rehearsal | depends on context |
| Speaking sample | mobile primary | natural voice recording | microphone in hand |
| Progress map | web primary | metacognition and analysis | big screen |
| Evening circle | mobile primary | bedtime closure | phone nearby |
| Guardians | both | friction-point support | appears where block happens |
| Peer/native club | live + both | interaction transfer | video stable on web; check-in mobile |
| Offline event | offline + mobile | real transfer | location/check-in |
| Payments/account | web primary | not learning | forms and policies |

## 3. Mobile Curriculum Shape

Mobile should offer:

- Today;
- session;
- SRS;
- speak;
- listen/shadow;
- evening;
- people/check-in;
- profile controls.

Mobile should avoid:

- long grammar tables;
- heavy typing;
- dashboards with too much analysis;
- long writing tasks.

## 4. Web Curriculum Shape

Web should offer:

- focus session;
- grammar workshop;
- writing workshop;
- reading studio;
- shadowing studio;
- vocabulary table;
- progress map;
- assessment archive;
- club rooms.

Web should avoid:

- being only a clone of mobile;
- hiding difficult but essential work in obscure tabs.

## 5. Live and Offline Layer

Live:

- coached speaking;
- group training;
- book/film clubs;
- task events.

Offline:

- cafe conversation;
- language walk;
- local partner session.

The app prepares, captures and recycles. It should not pretend that the screen itself is the whole language environment.

## 6. Split by Cognitive Load

| Cognitive demand | Best platform |
|---|---|
| quick recall | mobile |
| voice attempt | mobile |
| pronunciation loop | mobile |
| deep comparison | web |
| writing revision | web |
| long reading | web |
| social anxiety exposure | live/mobile |
| strategic review | web |
| habit rescue | mobile |

## 7. Design Consequence

Every screen must answer:

- what learning state is the learner in?
- does this platform fit that state?
- what is the next cognitive transition?

If a feature cannot answer that, it should be moved, merged or removed.
