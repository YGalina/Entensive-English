# ADR-014 · Определение освоенности по типам траекторий

Статус: предложено · 2026-07-15 · Architecture Decision Board
Закрывает: аудит §14 · Блюпринт: Части 2.1, 8

## Проблема
Единое определение mastery (6 проверок: понимаю → достаю → говорю в фрейме → адаптирую → после задержки → переношу) не согласовано с четырьмя типами траекторий той же самой конституции. Звук (тип III) не «достаётся от смысла», interaction (тип IV) не «понимается в контексте», грамматика (тип II) стартует без этапа узнавания. Одни и те же 6 проверок неприменимы ко всем.

## Почему важно
Mastery — это предикат, по которому система решает «единица освоена» (SRS-выпуск, прогресс-claims, гейты). Неприменимый предикат либо блокирует освоение навсегда (interaction никогда не пройдёт «достаю от смысла»), либо проверяется формально-бессмысленно.

## Фон
6 проверок писались от лексики (тип I) и обобщены без пересмотра — та же ошибка «единица=chunk», уже исправлявшаяся в v2.

## Научные данные
Конструкты разные: retention/recall для деклар. единиц `[R]`, intelligibility для звука `[R]`, interactional competence — отдельный конструкт в языковом тестировании `[R]`.

## Прецедент программ
CEFR разводит linguistic / pragmatic / sociolinguistic компетенции с разными дескрипторами `[P]`.

## Продуктовые следствия
«Что могу»-карта формулируется по-разному: «слово стало твоим» ≠ «тебя понял незнакомый слушатель» ≠ «ты починила сбой в разговоре».

## Технические следствия
Поле `masteryContract` на типе объекта (из таксономии v2 kind → тип траектории I–IV → набор проверок); прогресс-движок исполняет контракт, не универсальный список.

## Альтернативы
**A. Единый список 6 проверок** (как написано) с натяжкой интерпретаций.
 + одна модель
 − см. Проблема; натяжки скрывают неизмеримость

**B. Mastery-контракты по типам траекторий:**
 · Тип I (лексика/фразеология): все 6 проверок как есть.
 · Тип II (грамматика): употребил в трансформации → под временем → всплыло без запроса → после задержки → на новом содержании (5 проверок, без «понимаю»: знание — пререквизит входа).
 · Тип III (звук): различаю на слух → произвожу изолированно → во фразе → в своей речи → понял незнакомый слушатель.
 · Тип IV (взаимодействие): выполнил ход с моделью → с AI → с человеком в структуре → инициировал сам → в непредсказуемом.
 + каждый предикат измерим и осмыслен; согласовано с Частью 8
 − 4 контракта поддерживать; маппинг kind→тип должен быть полным

**C. Редуцировать mastery до «retention + transfer»** для всех.
 + минимализм
 − теряется лестница промежуточных состояний, на которой стоит SRS и прогресс-опыт

## Риски
B: объект без назначенного типа траектории → дефолт тип I молча; требовать явный маппинг в таксономии.

## Неизвестные
Пороговые значения внутри контрактов — это ADR-003, не этот.

## План валидации
Логическая проверка: каждый kind таксономии v2 имеет ровно один тип траектории и исполнимый контракт (таблица-аудит).

## Рекомендация
**B**; правка Части 2.1 блюпринта в 1.1 («определение освоенности — по типу траектории, инвариант: задержка + новый контекст обязательны во всех четырёх»).

## Уверенность
Высокая.

## Кто решает
Владелец: нет · Инженер: да (masteryContract) · Исследование: желательно (ревью контрактов SLA-специалистом)
