**Визуальная идентичность Living Content / «Бумага и чернила» сохраняется.** Аудит отвечает на вопрос «что из нарисованного выражает утверждённую систему, а что — прежнюю», не на вопрос «что красиво». Первый Batch 1 HTML отклонён как финальный UI и используется только как reference по состояниям.

**Сквозной диагноз (5 системных конфликтов, повторяются на многих экранах):**

- **К-А. CEFR из активности.** Ярлыки «B1 · Лимасол», «B1 → B2», «86 ч из ~200 до B2», «Ты в зоне B1» — уровень из внутренней активности запрещён (конституция §3 «Уровень — только из внешне-валидного среза»; progress_and_assessment_model_v2: CEFR estimate «НИКОГДА из активности»). Контентные метки сложности материала (карточка «B2 · 8 мин» в Библиотеке) — легальны: это свойство материала, не заявление о человеке.
- **К-Б. Стрик-язык.** «28 подряд», «28-я запись подряд» — против progress_experience («7 дней в июле», без «подряд») и не-целей миссии (§1: без стриков). Хранить историю можно, показывать «подряд» — нельзя (LX-конфликт К4).
- **К-В. Стражи внутри продукта.** Онбординг-страж, «страж в моменте», «стражи на пути» в Прогрессе, страж-перфекционизм в Письме — Г-3: аффективные ставки/IFS-стражи вне пилота и вне утверждённых экранов; психологическая интерпретация запрещена (§3).
- **К-Г. Галина внутри приложения.** Приветствие Галины (mobile 31, web 01/02) — именованное присутствие только лендинг/письма (спека S20; инвентарь §3).
- **К-Д. «Поток слов» как механика.** Word flood в сессии и Focus («Знаю это слово», «1 слово / 0,5 с») — exercise_architecture_v2: REDESIGN — остаётся только как прайминг 60–90 с (chunk-единицы, связь с контекстом дня, без самозаявлений «знаю», всегда → ретрив → output). Кнопка «Знаю» = self-report, не свидетельство (6 классов метрик).

Ниже — по платформам. Формат: экран → утверждённое назначение → вердикты (learning / UX / visual) → статус → что именно меняется. Полная таблица — SCREEN_MIGRATION_MATRIX_V1.md.

### Ядро пути

**02 «Сегодня» → S4 Path Hub / общий Today.**
Learning: ядро верное — один ведущий шаг (daily_learning_engine: «Сегодня — один следующий шаг, не меню»). Но фазовая полоса 4 цветов кодирует «поток слов → контекст → узнавание → сказать своё» — старая модель сессии (К-Д): утверждённые 6 фаз — прайминг · встреча · извлечение · производство · голос · резюме. SRS-карточка и клуб рядом с ведущим шагом создают конкуренцию (07_UX m2: «ориентация, не дашборд»). Таб-бар из 5 инструментов — вариант A, который split_v2 рекомендует пересмотреть (C-гибрид, решение владельца). UX: вход/выход валидны. Visual: **эталон системы** — ведущая карточка (2px терракота, тень), честные часы с подписью «Пауза, не потеря» — канон. **Статус: ADAPT.** Изменить: подпись фаз, периферию притушить (тихие факты, без CTA), таб-бар — после решения о навигации. Для пилота уже заменён хабом Batch 1 (1b).

**03 «Сессия · поток слов» → S5 фаза 1 (прайминг).**
Learning: конфликт К-Д — карточка со словом и кнопкой «Знаю» тренирует узнавание с самозаявлением; утверждённый прайминг — тап-послушать, без заданий и без клеймов. Visual: карточка слова (Lora, амбер-маркер) переиспользуема. **Статус: ADAPT** (механика: убрать «Знаю»-кнопки, тап-послушать, 60–90 с, chunk-единицы; связь с текстом дня видима).

**04 «Сессия · контекст/перевод» → S5 фаза 2 (встреча).**
Learning: точно по движку (связный вход, noticing амбер=новое/мята=знакомое, тап-перевод — «перевод всегда рядом»). UX: ок. Visual: эталон. **Статус: KEEP** (production clean-up: подпись фазовой полосы, состояния загрузки озвучки — неблокирующие).

**05 «Сессия · сказать своё» → S5 фазы 4–6.**
Learning: свободный ввод есть; отсутствуют: фаза 3 «извлечение» (смысл→форма, английского на экране нет, лесенка опоры — центральный механизм для нашей ЦА), мягкий надж/«оставить как есть», голосовая фаза с полным жизненным циклом записи, резюме с плашкой честности. UX: частичное покрытие фаз; safe exit ≠ completed не показан. **Статус: ADAPT** (дорисовать фазы 3/5/6 и все состояния S5; тишина в 4–5 — никаких подсказок во время ввода, лесенка живёт только в фазе 3 — C1-различие из 07_UX).

**06 «Прогресс» → S18.**
Learning: три конфликта — «86 ч из ~200 до B2» (обещание уровня к объёму часов: против curriculum_v2 «красная линия»; CEFR из активности К-А) · «Записать статус дня голосом · 28 подряд» (К-Б) · «страж как факт пути» (К-В). Дорожки «Понимание/Речь» с ярлыком «B1+» — К-А. UX: способности наверху — правильная иерархия (progress_experience). Visual: чек-лист «что могу» с мятными тиками, тихие полосы — переиспользуемы. **Статус: REBUILD IN LIVING CONTENT** (заявления только по классу свидетельства; «данных пока мало» — честное состояние; часы — ориентир без «до B2»; письменное ≠ устное).

**07 «Вечерний круг Focus» → нет утверждённого экрана.**
«28-я запись подряд» — К-Б. **Статус: FUTURE REFERENCE** (решение владельца до любой работы; стрик-строку убрать при любом исходе).

## 5. ФИНАЛЬНЫЙ СИНТЕЗ (по D-02 §Final)

1. **Реально переиспользуемо:** визуальный язык переиспользуется почти полностью (палитра, типографика, карточки, маркировка слов и honest-tone паттерны). Из 55 slices-v2 источников только 3 имеют статус KEEP (mobile 04, mobile 22, web 13); значительная часть требует ADAPT. Проценты не фиксируются до раздельной построчной классификации всех сгруппированных источников.
2. **Эталоны качества:** mobile 02 «Сегодня» (ведущая карточка + честные часы) · mobile 04 «Контекст» (амбер/мята + тап-перевод) · mobile 22 / web 13 «Читалка» · focus 01 (визуал «свет лампы») · mobile 32 (офлайн-честность) · mobile 35 (тон сообщества).
3. **Красивые, но методологически устаревшие:** mobile 06 / web 06 «Прогресс» (часы-до-B2, стражи, подряд) · mobile 30 «Проверка уровня» · mobile 31 / web 02 «Галина» · mobile 20/33 «стражи» · web 05 «Навыки» · focus 01 (механика фазы).
4. **С нуля в Living Content:** S3 · S7–S13 оценочный протокол · S14 AI Summary · S17 My Artifacts · S27 библиотека состояний · journey целостности данных (M3) · waitlist-опыт (M4). Batch 1 не считается утверждённым визуальным покрытием.
5. **Первый исполняемый батч** должен заново закрыть связный вход пилота и старт обучения в Living Content: S1/S2/S3/S4/S7/S8 с использованием существующих эталонов и Batch 1 только как state reference. После его визуального утверждения расширять протокол S9–S13 и Recovery S6.
6. **Решения владельца:** Вечерний круг (future/убрать) · модель навигации A/инструменты vs C/гибрид · судьба стражей как brand-элемента вне продукта · активация S25 через governance · серия в письмах. Различие scaffolded retrieval и свободного производства уже разрешено в Interaction Architecture и не является решением владельца.
7. **Следующее действие после одобрения:** выполнить исправленный первый journey-батч по D-03, показать владельцу default screens и только после одобрения расширять состояния.

Аудит не меняет дизайн и код; ничего замороженного не переоткрыто; нерешённые противоречия помечены, не решены.
