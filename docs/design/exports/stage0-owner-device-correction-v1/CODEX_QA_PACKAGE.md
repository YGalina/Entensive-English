# CODEX QA PACKAGE · Stage 0 · Owner Device Correction v1

Пакет на проверку готовности к реализации. Основание — обратная связь владельца с физического Android-устройства. Ни один принятый экспорт не изменён: Default v2, States v3 и Developer Handoff v3 остаются в силе; настоящий пакет — дельта поверх них.

| Артефакт | Роль в проверке |

| `Stage 0 · Owner Device Correction v1.dc.html` | источник истины по визуалу дельты |

## 2 · Критерии приёмки

### D1 · Завершение стартовой точки
- [ ] Вставлено после 28-го ответа, до первой тренировки; отдельного экрана «результат» не существует.
- [ ] Шапка и полоса прогресса — те же, что на элементах стартовой точки; полоса 100 %, счётчик `28 из 28`.
- [ ] Порядок чтения: заголовок → объяснение → разделитель → строка перехода → действие.
- [ ] Ровно одно действие. Нет: поэлементной правильности, ответов, баллов, уровней, процентов, списка ошибок.
- [ ] Возврат назад с этого экрана не открывает ответы и не даёт переиграть стартовую точку.

### D2 · Клавиатура открыта
- [ ] Активное поле и набранный текст всегда выше клавиатуры при любой длине текста.
- [ ] Формулировка задачи читаема над полем; на узком экране уменьшается только размер заголовка (27 → 25 извлечение, 26 → 21 производство), текст не сокращается.
- [ ] Ввод — одно непрерывное состояние: каретка и рамка фокуса не мигают между символами, клавиатура не «схлопывается» после символа.
- [ ] Основное действие достижимо обычной прокруткой; прижатие над клавиатурой не требуется и уход действия ниже видимой области при длинном тексте — норма.
- [ ] Размеры: поле производства min-height 118 (рост по содержимому, далее внутренняя прокрутка), извлечение min-height 58, слот вариации min-height 64.
- [ ] Фокус: border 1.5 #4A7BA6 + каретка 2 px того же цвета, без внешнего кольца.
- [ ] Клавиатура 390: клавиши 32 × 42, gap 5, отступы рядов 10/6/24, служебные 44. 360: 29 × 40, gap 5, 8/6/20, служебные 40. Фон #E3DAC4.
- [ ] Автоисправление, автокапитализация и проверка орфографии выключены; на экране присутствует `Автоисправление выключено`.
- [ ] Текст сохраняется по паузе ввода и при уходе с экрана; сворачивание приложения и обрыв сессии текст не теряют.

### D3 · S14, четыре состояния
- [ ] Композиция замороженного Batch C S14 переиспользована; нового экрана резюме нет.
- [ ] **A** выполнено + рамка: признание, до двух вариантов, грамматика к случаю, плашка честности, одно действие.
- [ ] **B** по теме без рамки: признание по теме, ровно одно приглашение ко второй версии, **один** вариант в `ЕЩЁ ТАК ГОВОРЯТ`, плашка честности целиком видима без прокрутки, её текст сохранён без молчаливой правки.
- [ ] **C** одна–две зацепки: мягкая самопроверка, **максимум два наджа**, затем `Попробовать ещё раз` и тихое `Оставить как есть`.
- [ ] **D** разбор не получился: текст недоступности + **реальное** `Попробовать ещё раз` + неблокирующее `Дальше`.
- [ ] Состояние D никогда не является дефолтом.
- [ ] Плашка честности присутствует только в A, B, C.
- [ ] Ни одно состояние не оценивает произношение и содержание записи.
- [ ] Красного нет; балла, процентов, CEFR и исчерпывающей правки нет; бинарного «правильно / неправильно» для свободного вывода нет.

### D4 · S3, три равных ответа
- [ ] Три полноширинных вертикальных выбора; горизонтальный ряд из трёх кнопок отсутствует.
- [ ] `min-height: 60`, вертикальный паддинг 14–16, `line-height 1.3`; длинная метка переносится, не обрезается.
- [ ] Минимум доступности 44 не нарушен ни при каком масштабе.
- [ ] `Не могу оценить` идентичен первым двум по ширине, форме, рамке, высоте, весу и размеру шрифта, фону.
- [ ] Каждый вариант достижим очевидной вертикальной прокруткой на 360 × 800 и при системном тексте 200 %.
- [ ] При 200 % карточка контекста может уходить выше области видимости; вопрос остаётся первым в порядке чтения.

## 3 · Матрица проверки на устройствах

Обязательные пересечения: **360 × 800** и **390 × 844** × системный текст **100 % / 200 %** × клавиатура **открыта / закрыта**.

| Экран | 360/100 | 360/200 | 390/100 | 390/200 |
|---|---|---|---|---|
| Завершение стартовой точки | ✓ | ✓ | ✓ | ✓ |
| Извлечение, клавиатура открыта | ✓ | ✓ | ✓ | ✓ |
| Свободный вывод, клавиатура открыта, длинный текст | ✓ | ✓ | ✓ | ✓ |
| Управляемая вариация, клавиатура открыта | ✓ | ✓ | ✓ | ✓ |
| S14 A / B / C / D | ✓ | ✓ | ✓ | ✓ |
| S3 | ✓ | ✓ | ✓ | ✓ |

Общие правила кадра: gutter 24 на 390 и 22 на 360; прокручивается только средняя область, шапки и внешняя шкала дня фиксированы; хром телефона из макетов не реализуется — системный статус-бар и safe-area берутся во время выполнения; зоны касания минимум 44 × 44, основная кнопка 56.

## 4 · Регрессии, которые пакет не должен вызвать

- [ ] Матрица States v3 не изменена: `C-B9-SAID` остаётся способом завершить B9 без записи, `C-F5-SKIP` — только для общего опционального сценария записи.
- [ ] Полное завершение = ядро + управляемая вариация + две произнесённые версии B9; пропуск вариации даёт только короткое закрытие (переиспользуется существующий S03, отдельного экрана нет).
- [ ] Короткий путь: пять шагов прогресса, без DayProgressRail; переключение пути доступно только из плана и возобновления.
- [ ] `RetrievalCounter` — Living Content-пилюля со значениями `1 из 3` / `2 из 3` / `3 из 3`, подчинена содержанию упражнения и не путается с прогрессом дня или ядра.
- [ ] Запись автоматически останавливается на 60 секундах.
- [ ] Все опорные чипы статичны и не интерактивны.
- [ ] Адаптивных подсказок, коррекции и фидбэка во время производства нет.
- [ ] «Назад» с первого экрана блока возвращает к плану дня с сохранением работы.

## 5 · Firewall (проверить нулевые вхождения)

`пилот` · `срез` · `протокол` · `SRS` · `DLE` · `retrieval depth` · `shadow` · `core` · имена состояний · S-номера в учебном тексте. Гендерно-нейтрально, без вины и давления, без обещаний «появится позже», без эмодзи, без красного как цвета ошибки.

## 6 · Вне области

- Отдельная визуальная концепция для Android — не делается; одинаковая иерархия и одно доминирующее действие на всех поддерживаемых ширинах.
- Оценка произношения и содержания аудио — до появления отдельного речевого конвейера.
- Любые правки утверждённого учебного текста.

## 7 · Ожидаемый выход проверки

1. Подтверждение, что четыре группы дельты реализуемы без противоречий с v3.
2. Список мест, где аннотация недостаточно однозначна для реализации (с указанием экрана и пункта).
3. Список потенциальных регрессий против раздела 4.
4. Вердикт: готово к реализации / требует уточнения владельца.
