# Intensive English — полный план продукта и разработки

Status: owner control baseline · 2026-08-08

Этот план объединяет ранее разрозненные дорожные карты. Он не меняет продуктовую архитектуру и не объявляет старые материалы автоматически утверждёнными.

## Правило выполнения

Работа идёт строго по gate, указанному в таблице. Codex не начинает следующий этап, пока результат текущего этапа не доступен владельцу в понятном виде. Любой UX/UI реализуется только после отдельного явного утверждения владельца.

## Критический путь сейчас

1. Зафиксировать этот владельческий контур управления.
2. Провести независимую методическую QA всей семидневной Stage 0 программы.
3. Составить единый end-to-end UX первого запуска и Дня 1, включая каждое состояние и действие.
4. Получить единый Fable UI package и показать его владельцу целиком.
5. После `УТВЕРЖДАЮ UX/UI` реализовать только этот package.
6. Провести полный Android regression и получить `ПРИНИМАЮ СБОРКУ`.
7. Только затем переходить к производству и дизайну Дней 2–7.

## Запрещённые обходы

- реализовывать экран по одному prompt без полного flow-review владельца;
- считать Codex QA заменой продуктового решения владельца;
- считать старое частичное одобрение разрешением на новый связанный UX;
- переходить к следующему дню, web, оплате или backend, пока текущий gate не закрыт;
- возвращать legacy onboarding, автоматический word flow, word-flood, музыку, coach upsell, guardians, streaks или levelcheck;
- заявлять speech analysis, CEFR, cloud sync или человеческую проверку без реальной системы.

## Отчётность Codex

После каждого рабочего блока Codex обновляет:

- этот план — если изменился этап или критический путь;
- `docs/owner/UX_UI_APPROVAL_REGISTER.md` — если появился или изменился экранный пакет;
- `.ai/DECISIONS.md` — только после явного решения владельца;
- `.ai/SESSION.md` и `.ai/TASKS.md` — фактический активный gate;
- Git commit — только для проверенного ограниченного результата.
