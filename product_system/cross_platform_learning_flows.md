# Кросс-платформенные учебные потоки

Дата: 2026-07-13 · (TASK 5) Как ОДИН учебный объект движется по системе. Каждый поток — end-to-end, привязан к петле (learning_loop) и дорожкам (progression). Общий бэкенд (LearningObject + журнал событий) обеспечивает бесшовность.

Легенда стадий петли: встреча→ноутинг→форма-смысл→произн→ретрив→продукция→вариация→task→спонтанно→отложенный→перенос→оценка.

## 10 сквозных примеров

### 1. Chunk из фильма (web) → автоматизм в клубе
Сцена на web → извлекла «it turned out» как блок → карточка на mobile (SRS produce) → диалог с персонажем (AI-ход, употребила) → 4/3/2 под временем → в онлайн-клубе на новом содержании → срез через неделю → в «что я теперь могу». Дорожки: phraseology→fluency→interaction→transfer.

### 2. Фразовый глагол из подкаста (mobile) → письмо (web)
Подкаст на mobile → «figure out» (перцепция безударного particle через shadowing) → смысл→форма в SRS → на web в письме «ответь Марку» употребила → тренер-резюме «а ещё так говорят» → отложенный ретрив → перенос в реальном письме. Дорожки: listening→phraseology→writing.

### 3. Грамматика present perfect (web-Мастерская) → речь (mobile)
«Заметь закон» из своего контента (web) → listen-then-build → на mobile фаза 4 «скажи через present perfect» = трансформация СВОЕЙ фразы → task repetition → спонтанно в диалоге → EIT-подобный срез. Дорожки: grammar knowledge→proceduralization→speaking.

### 4. Коллокация с L1-ловушкой (mobile) → клуб
«make a decision» (не «do») в контексте → cloze с L1-ловушкой → SRS produce → диалог с персонажем (поймал кальку → prompt на самоисправление) → клуб → перенос. Дорожки: collocations→accuracy→interaction.

### 5. Слово дня → биография → активное
Встретила в потоке (mobile) → тап-перевод «в мой словарь» → SRS обе стороны → сказала в вечернем статусе → стало «моим» (mine) → всплывает в чтении (ноутинг ×N) → в активе. Дорожки: breadth→depth→productive.

### 6. Просодия из shadowing (mobile) → сравнение (web)
Реплика героя (mobile караоке) → shadowing → на web сравнение своей записи рядом с оригиналом (ритм, не балл) → повтор → в своей речи (не имитация) → тренер отмечает мелодию. Дорожки: prosody→fluency.

### 7. Дискурс-ход «negotiation» (web диалог) → офлайн-встреча
Фрейм «what struck me…» в web-диалоге → опоры-формулы → онлайн-клуб (инициировала обмен) → офлайн-встреча в кафе (реальный перенос T6) → доска фраз встречи → в словарь → срез interaction. Дорожки: discourse→interaction→repair→transfer.

### 8. Возвращение после паузы реактивирует объект
Пропуск 7 дней → «вернуться с 5 минут» (mobile) → SRS достаёт просевшие chunks (retrieval strength упала) → микро-употребление → объект восстановлен, next_review пересчитан. Дорожки: consistency + удержание [R распад 4–6 нед].

### 9. Своя ссылка YouTube (mobile) → урок → прогресс
Нашла видео (mobile YouTube-поиск) → импорт → conveyor: 12 chunks + связный отрывок + вопрос фазы 4 → прошла сессию → артефакт → в дневник (web-Прогресс). Дорожки: input(свой контент)→output→transfer-evidence. [F «переведи свою жизнь»]

### 10. Тревожный объект (страх у микрофона) проходит аффект-гейт
Фраза, на которой замирает → страж-в-момент при заминке (mobile) → шёпотом→вслух → запись приватна → тренер-резюме тёплое ПОСЛЕ → та же фраза в клубе под лёгкой соц.-нагрузкой (T5 под аффектом) → де-автоматизация преодолена. Дорожки: confidence(гейт)→fluency-под-нагрузкой→WTC.

## Что обеспечивает бесшовность (требования к бэкенду)
- Один `LearningObject` с полями рецептив/продуктив/скорость/контексты/next_review/transfer (см. learning_data_model).
- Журнал событий (append-only, идемпотентный) — уже спроектирован (Фаза C): encounter/notice/produce/artifact/review пишутся с любой поверхности.
- Направление-специфичный SRS (recognize + produce как раздельные силы одного объекта).
- Privacy: голос/дневник private-by-default; синк по согласию.

## Конфликт легаси
Сейчас объект расщеплён: `Word` (контент) + `SrsCard` (recognize/produce) + `OutputArtifact` (вывод) живут раздельно, связь по строке `en`. Для сквозных потоков нужен **единый LearningObject**, агрегирующий это (см. learning_data_model — migration). Не переписывать разом; расширять поверх существующего srs.ts/output.ts.
